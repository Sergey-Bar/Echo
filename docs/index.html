Hear the whole city in seconds.

Echo works out which noise detectors fire across a simulated city, frame by frame, with exactly the same answer as the original simulator. Runs that took hours now take seconds.

View the code on GitHub See the results

The problem

Vehicles drive through a city. Their noise spreads along the streets and around buildings, never through them. Detectors around the city fire whenever the noise they hear adds up to a threshold. The job is to report, for every detector, exactly which frames it fired on.

The original simulator rebuilt a full noise map for every vehicle on every frame. On a busy city that meant about 42 hours for one run.

Streets carry sound

A vehicle's noise at a cell is its loudness minus the number of street steps to get there.

Detectors add it up

A detector fires when the sum from all vehicles reaches the threshold.

Exact or nothing

The output has to match the original simulator to the frame, on every city.

One core, 4 GB

Up to 400×400 cells, 100 vehicles, 20,000 detectors and 50,000 frames, in under 10 minutes.

How Echo does it

Two observations remove almost all the work. The log only needs the noise at detector cells, not the whole map. And a vehicle's noise only changes when it moves to another cell, not on every frame.

  1. Listen from the detectors

    Echo measures street distances once from each detector, out to the loudest vehicle's reach. Distance on a street grid is the same in both directions, so this gives exactly the numbers the simulator computed from each vehicle.

  2. Turn routes into segments

    Each vehicle becomes a short list of "on this cell from frame a to frame b". Looping vehicles repeat the same lap, so Echo builds one lap and shifts copies of it in time.

  3. Add up changes, not frames

    When a vehicle arrives near a detector, its noise is added at that frame; when it leaves, it is subtracted. One cumulative sum gives every detector's exact noise on every frame, in a handful of numpy operations.

The route trick

Vehicles follow shortest paths, and when two paths are equally short the simulator's queue picks one in a specific order. We showed that this order always gives the alphabetically first shortest path, reading moves as up, down, left, right.

So Echo measures distances from the goal once, then walks from the start, always taking the first direction that gets closer. That gives the same routes as the original, checked against it on 5,000 random routes.

Results

Same city, same answer, between 135 and about 285,000 times faster. Times below were measured on one CPU core in a Linux container with a 4 GB cap. The "before" times for the four large cities are projected from the original's first 20 frames, because full runs take hours.

Bar length uses a log scale: each step is ten times longer.

Proof it is exact

Fast is easy if you're allowed to be wrong. Echo is not, so every change had to pass all of these before it was kept.

  • Every example city gives a log identical to the original's reference, and frame-by-frame snapshots match on the small city.
  • 300 random cities, built to hit edge cases: walled-off regions, vehicles louder than the map, parked vehicles, waits, loops, runs cut short, thresholds from trivial to unreachable. Each one is compared with the original simulator.
  • 5,000 random routes compared with the original path search, including a goal that cannot be reached.
  • The tests were checked by breaking the code on purpose: changing "at least the threshold" to "above the threshold" makes them fail. They also caught a real bug during development.
  • The included demo city runs in 0.03 s with Echo and 10.6 s with the original engine, with identical logs. Anyone can rerun it.

Pushed to the limits

The examples each stress one thing. We built cities that stress everything at once, then ran them on a single core with a hard 4 GB memory cap, where going over the limit kills the run.

CityTimePeak memory
100 looping vehicles, 20,000 detectors, 50,000 frames on 400×400169 s875 MB
100 one-way vehicles with 150 stops each, 20,000 detectors, 50,000 frames277 s929 MB

Both finish well inside the 10-minute limit and use under a quarter of the memory. The first one did not finish at all before looping vehicles reused their laps.

Run it

Python 3.12+ with numpy and pyyaml. The command line is the same as the original simulator's.

# install
pip install -r requirements.txt

# run the demo city: writes log.json
python -m citynoise run examples/demo.yaml

# watch it (uses the original frame-by-frame engine)
python -m citynoise run examples/demo.yaml --render

# make your own city
python tools/make_scenario.py examples/mine --vehicles 20 --detectors 500 --frames 20000

# prove it matches the original
python -m pytest tests

Echo by Sergey Bar. The baseline frame-by-frame simulator was provided as a performance challenge. The Echo engine, route planner, tests and benchmarks were built on top of it, with Claude Code and a custom agent setup.
